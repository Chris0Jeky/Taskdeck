# Go-to-Market and Marketing Strategy (Developer tool, early-stage)

## Your near-term goal
Not “sell.”  
Your near-term goal is: **get 5–20 people to use it weekly**.

## Positioning (simple)
- Local-first board that maintains itself.
- Review-first automation: nothing changes without approval.
- Keyboard-first speed.

## What to build for marketing (assets)
1) 60–120 second demo video (screen recording)
- capture messy note → triage → proposal diff → apply → board updated
- show “source/provenance” on a created card

2) Landing page (minimal)
- headline + 3 bullets
- install instructions
- screenshots/GIF
- “join beta” email capture

3) A “Why” doc
- why local-first matters
- why proposal-first exists (trust)

## Channels that tend to work for dev tools
- GitHub README and releases
- Hacker News / Reddit (only after the demo is solid)
- Dev.to / blog posts (show lessons, not hype)
- Discord communities / university communities
- friends/classmates as first users

## Content themes that will actually attract the right users
- “How I reduced task-management overhead”
- “Proposal-first automation: safe AI for personal productivity”
- “Local-first workflow tooling: exportability and control”

## Conversion and retention levers (PLG-ish)
Activation:
- time-to-first-value < 5 minutes (install + first board + first triage)

Retention:
- daily use feels easier than not using it
- you remove the “maintenance tax” that kills habit formation

Referral:
- shareable starter packs (export/import)
- screenshots of clean boards + automation diffs
